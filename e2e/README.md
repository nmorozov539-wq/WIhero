`perf.mjs` is a profile, not a check: at 6x CPU throttle and 390 × 844 it times Home settling, opening a book and an entry, scrolling, Hero mode, a card tap and a pan, and prints the long tasks. It makes 40 "Stress" books of 150 entries if they aren't there. Because it seeds a real library, it refuses to run unless `PERF_ALLOW_SEED=1` is set; use only a throwaway SillyTavern, never your own.

`perf-harness.mjs` is the disposable counterpart: a profile, not a check, of the in-memory browser harness (`e2e/desktop/harness.html` with `?perf=1`). It seeds 40 generated books, a 1,000-entry "Perf Big" book with a placed canvas and a 100 KB entry, and a long chat, all in the page's memory and localStorage; it needs no SillyTavern and never touches a real library. At 390 × 844 it records `?perf=1` cold Home, the earliest possible tap on a book, warm Home, opening and scrolling the big book, opening an entry, an A–Z sort, search typing, Hero mode (card tap, pan, inspector toggles with Show chat state off and on) and typing in the 100 KB entry (with the token-count stub's call count). The in-memory library resolves its reads immediately, so that tap is the earliest one the page can receive, not a tap while counts are still loading. One JSON line per step; `--rate` (default 6), `--runs` and `--out` are optional. The book-open and entry-open steps also carry a `perf` delta from `wihero.perf` (counters and timing regions). Run `node e2e/perf-harness.mjs`.

Run them against a throwaway SillyTavern, never your own: it changes the connection settings and the global lorebooks, and creates (then deletes) a character.

1. A SillyTavern 1.19.0 or 1.19.1 with fresh data (default Seraphina character), with this repo linked as `data/default-user/extensions/st-wihero`.
2. Copy `examples/WIHero-N1.json` and `examples/WIHero-Sample.json` to that SillyTavern's `data/default-user/worlds/`.
3. Start it (`node server.js --port 8000`, or set `ST_URL`).
4. `node e2e/mock.mjs &` (OpenAI-compatible mock on port 5001, logs prompts to `e2e/log/`).
5. `npm i --no-save playwright@1.55.0`, then `node e2e/n1.mjs`, `node e2e/n2.mjs`, `node e2e/n3.mjs`, `node e2e/n4.mjs`, `node e2e/n5.mjs`, `node e2e/n6.mjs`, `node e2e/n7.mjs`, `node e2e/n8.mjs`, `node e2e/n9.mjs` and `node e2e/n9-text.mjs` (also with `INSTRUCT=1`), and `node e2e/trackers-edge.mjs`. Set `CHROMIUM=/path/to/chrome` if Playwright's own browser isn't installed.

The older scripts (gating, editor, labels, folders, visuals, workspace, phone, branches) test the old UI and are in the git history; their checks now live in n1–n8.

`tools/st-drift.mjs` is not a browser check: it compares the SillyTavern code WI Hero copies or leans on (getStringHash, the decorators, matchKeys, sticky timing, the generate interceptor, and the exports and events it uses) in ST's latest release and staging with the fingerprints taken on the tested version (`tools/st-drift.json`). GitHub runs it weekly (`.github/workflows/st-drift.yml`); `node tools/st-drift.mjs --dir <SillyTavern>` checks a local copy, and `--update` takes the fingerprints again once a change has been checked and WI Hero follows it.
